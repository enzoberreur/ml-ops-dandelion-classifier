# Loom Demo Script - Bloc 4 (5 minutes)

Required flow: **Prediction API → CI/CD → Monitoring (drift, metrics) → Retraining**.
Record at 1920×1080, browser zoom ~110%. Have the stack already up
(`docker compose up -d`) and one training run completed so a model is served.

> Pre-flight (off-camera): `docker compose ps` all healthy · trigger
> `dandelion_data_pipeline` once · download `test_dandelion.jpg` / `test_grass.jpg`.

---

### 0:00-0:30 · Intro & architecture (README diagram)
"This is an end-to-end MLOps solution: a dandelion-vs-grass image classifier,
industrialised - Airflow orchestration, MLflow tracking, MinIO storage, a FastAPI
serving layer, CI/CD on GitHub Actions, and production monitoring with
data-drift detection and automated retraining." Show the README architecture
diagram and the service table.

### 0:30-1:30 · Prediction API (the product)
- Open `http://localhost:8501` (Streamlit). Upload `test_dandelion.jpg` → show
  prediction + confidence. Upload `test_grass.jpg` → show the other class.
- Open `http://localhost:8000/docs`. Call `GET /version` → point out `model_arch:
  resnet18`, classes, model source. Call `POST /predict` on an image → show the
  JSON (prediction + per-class probabilities).

### 1:30-2:15 · ML model & tracking (MLflow)
- Open `http://localhost:5500` (MLflow). Open the latest `dandelion-classifier`
  run → show params (`arch=resnet18`, epochs, lr) and metrics
  (`val_accuracy`, `val_f1`, precision/recall curves). 
- "ResNet18 transfer learning on ~400 images, ~0.90 accuracy / ~0.89 F1, fully
  reproducible - every run logs code, params and the model."

### 2:15-3:00 · CI/CD (GitHub Actions)
- Open the repo's **Actions** tab. Open the latest green `CI/CD` run.
- Walk the three jobs: **tests** (pytest: model, API, drift) → **build** (image
  pushed to GHCR) → **deploy** (Minikube apply + rollout wait).
- "Every push to main runs the tests, builds the image, and deploys to Kubernetes."

### 3:00-4:00 · Monitoring: metrics + drift
- Open Grafana `http://localhost:3000` → **Dandelion Classifier** dashboard:
  total predictions + p90 latency moving as you hit the API.
- Open the **Dandelion Data Drift** dashboard: `Dataset Drift Status`,
  `Share of Features Drifted`, per-feature PSI bars.
- Open `monitoring/drift/reports/drift_report.html` → "This is the drift report;
  PSI per feature, dataset-drift verdict. It's generated by Evidently in
  production, with a dependency-free fallback."

### 4:00-4:45 · Automated retraining
- Open Airflow `http://localhost:8080` → `dandelion_retrain_pipeline`. Show the
  graph: `sync → check_drift → train → refresh_baseline`.
- "Retraining runs monthly, and also on-demand gated by drift - same drift
  definition as the dashboard. `python -m retrain.retrain --reference-dir ... 
  --data-dir ...` only retrains if the incoming data drifted." Trigger the DAG to
  show it running (optional).

### 4:45-5:00 · Wrap-up
"Specs → model → serving API → CI/CD → monitoring → retraining: a closed MLOps
loop. Code, IaC and this demo are in the repo." Show the repo root tree briefly.
